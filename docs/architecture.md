# 梦境的结构与接口

Figure Scape 的 npm 包名为 `cortico-world-figure-scape`。Coo 使用 `desktop-live2d-pet` 作为 World ID，配置键、数据目录、事件类型、工具名和旧页面链接沿用这一 ID。Coo 拥有对话、记忆与工具调度。梦境负责角色身体、显示与本地操作。

| 责任域 | 主要入口和状态 |
| --- | --- |
| Coo 接入 | `src/definition.ts` 装配依赖，`src/world.ts` 接入事件、工具和面板。`src/chat.ts` 投影会话消息与投递状态。 |
| 运行协调 | `src/framework/model-domain.ts` 负责操作与持久化，`model-application.ts` 关联应用请求。模型与场景的提交共用 `body-transaction.ts`，忙时返回可重试的反馈。 |
| 模型资源与配置 | `src/live2d` 准备原始模型与 SDK 缓存。`src/framework/figure-library.ts` 导入形象包并单独保存用户覆盖。 |
| 身体表现 | `web/body-host.js` 连接身体帧，`web/figure-frame.js` 运行直载模型或形象包。动作词表按身体回报更新。 |
| 音频与同步 | `src/asr` 负责识别，`src/speech` 负责合成和编排。`web/framework/speech.js` 用播放器进度协调气泡、口型和动作。 |
| 场景 | `src/framework/presentation-service.ts` 持有应用状态。`web/desktop-system.js` 装配桌面、小屋、竖屏和壁纸实现。 |
| 呈现与输入 | `web/pet-app.js` 连接交互，`web/framework` 提供操作台、对话、触碰几何和窗口抓手。身体命中坐标和窗口位置各由所属模块维护。 |
| 编辑服务 | `src/framework/editor-backend.ts` 管理网页编辑会话和按来源保存的草稿。编辑与预览使用自己的一帧模型。 |
| 宿主适配 | `src/server.ts` 提供回环页面。`src/window-host.ts` 与 `host/` 管理梦境窗口的启停、穿透、截屏设置及 OBS 输出。 |

Figure Scape 主包通过 npm 发布。小屋世界在引擎页按需下载固定的 GitHub Release ZIP，校验附件大小、摘要与运行文件后安装到部署数据目录下的 `desktop-live2d-pet/cabin-runtime/`。已有兼容安装直接复用，完整的旧 npm 三包仍可离线装配。存档、头像和桥接状态保存在独立的 `desktop-live2d-pet/cabin-world/`。适配 ZIP 由 `scripts/prepare-cabin-runtime.py` 从已校验的上游 Windows 导出生成。

进入小屋世界时，先预留场景切换，再通过官方桥登记梦境角色的独立住户。`host/cabin-render.cjs` 复用沙箱预览生成透明帧，`host/cabin-world.mjs` 通过本机 WebSocket 推送二进制帧，Godot 复用住户纹理。桥完成登记后，Godot 补报存档住户的位置。梦境收到位置和首帧回执后请求旧窗口隐藏，得到确认后才显示游戏窗口。游戏确认显示后启用场景对话并通知 Coo。超时或断开时，宿主清理本次启动的进程并恢复原呈现。

## 场景接入规范

桌面、小屋、竖屏、壁纸和小屋世界使用稳定的场景 ID。工作台、右键操作台、场景窗口和 Coo 都读取运行端确认的当前场景。窗口准备期间，界面分别显示目标和进度。窗口关闭、隐藏或身体未就绪时，当前场景可以为空。旧接口里的 `presentation` 仍指梦境窗口自己的呈现，当前场景读取 `activeScene`。

### 命令与窗口

| 用户动作 | 行为 |
| --- | --- |
| 点击场景入口 | 在当前场景面板内打开该场景。返回箭头或 Esc 回上一级，恢复列表的滚动位置与触发控件焦点。 |
| 进入场景 | 发起切换并等待画面和输入就绪。梦境窗口隐藏或关闭时，可以设置下次启动的场景。 |
| 在壁纸库选择背景 | 设为背景，或替换当前壁纸。库保持打开，保留查询、滚动和当前任务反馈。 |
| 梦境场景窗口上的 X | 走同一切换流程返回桌面。操作台自身的 X 关闭操作台。独立游戏窗口关闭时走宿主的退出与恢复流程。 |
| 隐藏桌宠 | 隐藏身体显示并释放输入。保留当前所选场景和它的配置，供再次显示时使用。 |

### 切换与数据归属

- 场景请求绑定目标、请求标识和角色，首帧回执记录身体代次。模型应用和场景切换共用提交锁。目标首帧准备好后保存场景配置，保存成功才允许渲染端结束切换。配置写入失败时渲染端恢复原画面，窗口断开时回退本次已经写入的场景与壁纸选择。
- 加载失败、取消或断连时，释放候选场景的输入、音频和临时状态，恢复之前已确认的场景和位置。恢复也按实际显示确认。独立宿主报告窗口就绪和退出，场景层负责对外解释这些回执。
- 角色大小、位置与交互能力由各场景持有。桌面依据当前显示器的工作区，小屋持有家具落点和遮挡，竖屏持有 9:16 区域与触摸方式，壁纸持有背景、音量、X/Y 与落地线。小屋世界的独立宿主持有地图、住户和存档。
- 竖屏用身体报告的静止轮廓确定 100% 构图，大小滑杆在此基础上连续缩放。动作变化沿用同一取景。换角色时先在隐藏图层计算并绘制候选构图，再显示新角色。
- Coo 持有会话和事件记录。场景确认变化后同步当前身体和场景。回复先写入事件记录，再由已确认的呈现显示。切换时通过发言标识和播放位置交接，按目标场景的能力显示气泡或字幕。小屋显示即时小气泡，梦境在 Coo 内的扩展对话面板合并原版与梦境的历史。
- 发消息时区分 Coo 接受投递与仅归档。仅归档保留输入供重试，归档条目不进入新的会话显示。历史分页沿用原始游标并保留跨页撤回及延迟送达的顺序。Core 的投递回调只发给消息所属的 World。原版桌宠有明确的送达记录时，梦境才能关联原版提问并保存尚未记录的回复。
- 触碰上报按手势发生时的场景和人物记录。只合并同一场景、同一身体和同一区域的相同手势。若上报前切了场景，触碰正文注明当时的场景，Coo 的可用状态继续反映已确认的新场景。

### 对话入口与运行记录

Coo 左栏「对话」用于用户与原版桌宠直接交流，沿用 Desktop Pet 的事件和 `pet_say`。梦境场景的文字、语音转写和发言由梦境 World 归档。场景气泡和梦境对话记录读取这些事件，音频和动作由当前场景负责播放。

Coo 原版的「控制台对话」通过 `console.message` 和 `console_send` 收发消息。高级模式的控制台时间线可查看梦境消息的投递记录、`live2d_pet_say` 的调用参数和回执。梦境侧的 `src/chat.ts` 负责对话记录中的正文、撤回和送达顺序。

新增场景或调整现有场景，须核对工作台、右键入口、窗口退出和 Coo 侧状态。至少验证正常进入、加载失败恢复、返回桌面和发言中切换。壁纸还应验证更换背景后库保持可操作，小屋世界还应验证窗口意外退出后恢复先前呈现。桌面、竖屏或小屋的角色大小变更应仅更新所选场景。

四种梦境呈现和小屋世界共享场景提交锁，宿主的启停由各自的运行服务执行。从小屋世界切往其他场景时，已连接的桌宠在后台准备目标首帧。目标成功确认后小屋世界才退出，目标失败时继续使用原住户。桌宠窗口不在线时可继续留在小屋世界，也可直接退出后再启动桌宠。独立游戏窗口的关闭键沿用相同的退出流程。

小屋世界通过对话面板读取同一会话。梦境住户复用语音播放器和动作词表。切换桌宠与梦境住户时，目标首帧就绪后向原宿主索取当前段落、已显示文字、已触发的动作和音频播放位置。目标使用同一个发言标识接续，切换期间收到的新回复跟在原有队列后。若目标换了角色，只携带原发言的文字和声音。原生住户沿用文字呈现。原宿主崩溃或未能回报进度时，完整正文仍在 Coo 会话里。

梦境住户的渲染器在首次呈现前上报当前角色、身体代次与实际可用动作。旧身体没有提供动作列表时，沿用形象包的声明，并保留声明来源。场景面板与 Coo 读取同一份能力。动作指令带请求编号，独立动作由实际身体接受后进入播放状态。Coo 可以用 `live2d_pet_status` 的 `actionId` 查询请求。身体报告结束对应 `completed`，预计时长走完对应 `elapsed`。小屋切换会结束独立动作，续播只接续发言及其动作。原生住户沿用 `cabin_*` 游戏活动，并通过 `cabin_task` 查询完成状态。

## 从来源到当前身体

原始 Live2D 由梦境准备模型资源和 SDK 缓存。Coo 形象包保留作者提供的入口与默认配置。Spriter 源工程和小屋世界住户在梦境中以形象包渲染，仍保留各自的来源。模型库与 `character.open` 共享角色来源和可编辑任务。形象包仅在作者提供动作或装扮时开放对应任务。没有对应任务的直达链接落到外观页。形象包用 `character.saveFigure` 保存用户覆盖，失败后可用同一配置版本重试应用。模型、装扮、触碰、色相与亮度偏好按来源保存。小屋世界本身持有住户和存档。形象包配色作用于透明角色图层，恢复默认会清除这层用户偏好。

运行端保留当前确认的身体，候选加载成功并报告首帧后才切换。当返回已保存但尚未应用时，配置已落盘，窗口仍等待下一次应用。接口状态要分别看操作结果、模型代次及窗口首帧就绪。渲染帧以受限资源地址访问选中的角色。草稿另有写入版本。更新、保存或清除时需要匹配当前版本。网页检测到其他标签提交时保留本页输入，允许读取已有草稿，或经确认用本页内容替换草稿。

动作资源的单独试播只在预览播放器里短暂占用该资源的参数，姿态的正式绑定仍校验复位片段。更换预览画质时，编辑台从旧画布撤销待确认的试播，等新画布就绪后重新呈现草稿取景和配色。

## 角色渲染

| 角色来源 | 渲染入口 | 网格和贴图 |
| --- | --- | --- |
| 原始 Live2D（`.model3.json`） | 加载本机 Cubism Core 和 Live2D 后端，现有后端申请 `webgl`（WebGL 1）上下文。[直载入口](../web/direct-model-body.js) · [Live2D 后端](../live2d-runtime/pack/backends/live2d.js) | 模型网格和变形由 Cubism 处理。资源准备读取 `FileReferences.Textures`，渲染时按贴图索引绑定。 |
| Coo 形象包（`figure.json`） | 调用形象包声明的工厂，并传入 Coo Kit。[渲染帧](../web/figure-frame.js) | 形象包选择渲染方式，可自行绘制，也可使用 Kit 的 `createRig`。[Kit 渲染器](../web/kit/rig.js) |

`createRig` 是 Coo Kit 的分件网格渲染器，大肥鱼就用这套机制。它优先申请 WebGL 2，必要时回退到 WebGL 1。部件绑定到一条变形链，每帧可以旋转、缩放或弯曲。形象包可以把多个部件放在同一张贴图里，再用各自的 `uvBox` 指定采样区域。

## 常用接口

| 入口 | 用途 |
| --- | --- |
| Coo 的 `world:desktop-live2d-pet` 面板 | `runtime.state`、`resources`、`runtime.openEditor`、`presentation.select`、`operation.get`、`operation.cancel`。 |
| 本机 `/api/editor` | 浏览器编辑凭据访问。角色打开、草稿增删、保存及应用，分别返回自己的结果。 |
| 本机 `/api/bodies/:id` 和 `/model-frame` | 角色资源描述与沙箱渲染。 |
| `desktop-live2d-pet.touch` | Coo 触碰事件，支持手势、区域 ID、名称、次数和说明。正式投递受触碰全局设置与角色规则约束。 |
| `live2d_pet_status` 和 `live2d_pet_say` | 查询可用身体和当前场景。发言先存进会话，窗口可用时进入播放。 |
| 本机 `/overlay` | 用户启用 OBS 画面后提供透明浏览器源。 |

Windows 由窗口宿主在前台选区出现时临时让出置顶、鼠标和键盘。选区可以停在任务栏上沿，最小化或被 DWM 隐藏后恢复常态。此规则适用于桌宠窗口承载的桌面、小屋、竖屏和壁纸。显示页的采集排除设置与 OBS 浏览器源各自沿用原有命令。
| 工作台 `phone.*` | 查询状态、启停局域网连接、生成配对码、解除配对和下载签名 APK。 |

Cabin World 在独立 Godot 窗口运行。梦境沿用场景页和同一 Coo 会话，经本机桥读写住户的世界状态。世界的位置、玩法和存档由 Cabin World 管理。梦境选择稳定住户编号，向 Coo 暴露受其约束的 `cabin_*` 工具，并通过 `cabin_task` 查询真实任务回执。桥凭据只在后端读取，窗口或桥断开后可重新连接，未确认的操作不自动重发。

## Figure Pet 连接

工作台通过 Coo 面板管理连接。`src/phone-link/service.ts` 随梦境 World 启停连接器，默认关闭。用户启用后才监听局域网 HTTPS 端口 17832。TLS 身份和配对设备记录沿用同一部署下的 `yume-pet/`。配对码限时且可使用一次，后续请求用手机的设备令牌校验。配对文件由运行时创建，存放在部署数据目录。

连接器按手机选择的来源转发到梦境或原版桌宠的聊天面板。会话和历史由 Coo 持有，发送回执沿用对应面板的消息 ID。角色目录与装扮取自所选来源。资源从当前宿主的回环地址获取，按角色资源版本匹配，方便手机在版本变动后重新同步。

APK 下载复用 Coo 的文件响应接口。下载入口读取 `src/phone-link/client/` 中的签名安装包。Android 应用源码、签名构建与 APK 由 Figure Pet 项目维护，连接器源码随本仓库维护。

## 数据与设备

模型文件、草稿、形象包快照、壁纸与缓存保存在本机 Coo 数据下。服务认证信息由 Coo 的凭据接口保存。语音识别使用用户选中的本机或远端引擎。远端转写会收到该次收音，远端合成会收到该次朗读文本，动作编排服务会收到对应台词和参数信息。

安装归档包括程序源码、前端产物和许可文本。Live2D Core 与 Framework 来自经校验的本机缓存，首次需要下载时由用户确认组件许可。原始角色、设备录音、会话和服务认证信息按部署保管。
